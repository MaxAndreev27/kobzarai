# Експериментальний локальний API

Це однокроковий прототип: він не зберігає історію, не використовує порогову
відмову та не перевіряє автоматично достовірність відповіді
моделі. Знайдені фрагменти можуть бути нерелевантними, а модель — помилятися.
API призначене лише для локальної розробки: автентифікації та контролю
доступу немає, тому не відкривайте його в мережу.

Потрібні Python 3.12, `uv`, запущений локально Ollama з `qwen3:8b` та
локальний корпус. За замовчуванням API використовує копію без помилково
атрибутованого запису ID 3984. Якщо копії ще немає, створіть її один раз із
вже зібраного корпусу:

```sh
cd ml
uv run python evaluation/audit_corpus.py \
  --report outputs/corpus-audit-v1.json \
  --filtered-output outputs/poems-uk-audited-v1.jsonl --quarantine-id 3984
cd ..
```

Файли не перезаписуються. Для іншої копії задайте `KOBZAR_CORPUS` шляхом до
JSONL перед запуском. Якщо корпус не існує або некоректний, запуск завершується
помилкою; немає автоматичного переходу на неперевірений корпус.

Запуск із кореня репозиторію:

```sh
uv sync --project backend
uv run --project backend uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Для діагностики backend у VS Code виберіть `backend/.venv/bin/python` як
інтерпретатор: окреме середовище `ml/.venv` не містить залежностей API.

`POST /chat` приймає `question` і обов'язковий `mode`: `title` для
лексичного пошуку за назвою або `quote` для однієї цитати в лапках з
щонайменше чотирьох слів. Режим `auto` спершу шукає таку цитату по всьому
корпусу; якщо її однозначно знайдено, використовує цитатний пошук. Якщо
цитата неоднозначна, не приписує її одному твору. В інших випадках шукає
твір за назвою та фрагменти в ньому. Без розпізнаної назви чи точної
цитати повнотекстовий семантичний пошук по всьому корпусу не виконується.
Виняток — явний запит на всі місця входження одного слова (слово можна
взяти в лапки, наприклад: «Знайди всі місця, де зустрічається слово сад»):
API шукає
по всіх текстах корпусу, повертає кожен рядок зі словом або формою з тією
самою основою та не викликає модель. Відповідь містить кількість збігів і
кількість рядків; `retrieval_status` дорівнює `term_matches` або
`term_not_found`.
Опціональний `retrieval_method` має значення `lexical` за замовчуванням
або `hybrid` для поєднання лексичного та семантичного пошуку в одному
знайденому за назвою творі. `hybrid` доступний для `mode: "title"` і
`mode: "auto"`; поєднання з `quote` повертає HTTP 422. В `auto` точна
цитата завжди використовує лексичний пошук. Для гібридного пошуку потрібна локальна модель
Ollama `bge-m3:latest` (наприклад, `ollama pull bge-m3`). Ембеддинги
фрагментів кешуються в пам'яті процесу за твором і версією моделі. Перший
запит до довгого твору може бути повільним; перезапуск очищує кеш.

Опціональний `answer_mode` має значення `generated` за замовчуванням.
Значення `sources` повертає знайдені фрагменти без виклику чат-моделі:
вони можуть не містити відповіді, і їх потрібно перевіряти самостійно.
Цей режим зменшує ризик вигаданого тексту моделі, але не гарантує
релевантність джерел і не формує відповіді природною мовою.
Якщо джерело не знайдено, для загального запиту в режимі `generated` можна
явно передати `allow_ungrounded: true`: модель відповість без джерел, а
результат отримає статус `ungrounded`. Така відповідь не підтверджена корпусом
і може містити вигадки. Запит із цитованою назвою чи фрагментом, для якого
пошук повернув відмову або неоднозначність, не передається моделі без джерел,
навіть якщо прапорець увімкнено. У режимах `auto` та `title` однослівний
словниковий запит на кшталт «що означає слово …» залишається загальним.
Режим `quote` завжди вимагає джерело. За замовчуванням `allow_ungrounded`
дорівнює `false`. У режимі `sources` генерація не виконується, навіть якщо
прапорець увімкнено.

```sh
curl -sS http://127.0.0.1:8000/chat \
  -H 'Content-Type: application/json' \
  -d '{"mode":"title","question":"Яку річку Україна називає братом у «Розритій могилі»?"}'

curl -sS http://127.0.0.1:8000/chat \
  -H 'Content-Type: application/json' \
  -d '{"mode":"title","question":"Хто зачарував дівчину у «Причинній»?","retrieval_method":"hybrid","answer_mode":"sources"}'
```

У відповіді є `experimental`, `status` (`generated`, `ungrounded`, `sources` або `refused`),
`retrieval_status`, `retrieval_method`, `answer`, `sources`, `model` і `corpus_sha256`. Джерела
містять ID, назву, URL, зміщення та текст фрагмента. `generated` означає
лише успішну генерацію, не те, що відповідь підтверджена: сама модель може
відмовити або помилитися. Для запитань за знайденим твором відповідь
обмежена двома реченнями й має містити цитату, яка підтверджує тезу;
це інструкція моделі, а не формальна гарантія перевірки цитати.
`ungrounded` означає дозволену генерацію без знайдених джерел;
`sources` порожній, а `retrieval_status` пояснює результат пошуку.
Такі відповіді обмежені двома короткими реченнями й не повинні вигадувати
частоту вживання слова чи мотив автора, якщо джерел не знайдено.
У режимі `auto` поле `retrieval_method` указує метод використаного пошуку;
для неоднозначної цитати воно також дорівнює `lexical`.
`not_found` не доводить, що твір або цитата не існують.
У режимі `sources` та при відмові поле `model` дорівнює `null`.

Помилка Ollama або неповна відповідь повертає HTTP 502, тайм-аут — 504,
помилка вводу — 422. Модель і адреса Ollama фіксовані; використання GPU не
перевіряється. Для оцінювання людиною див. [інструкцію](../ml/evaluation/HUMAN_REVIEW.md).
Після оновлення коду перезапустіть сервер, щоб нові параметри набули чинності.
